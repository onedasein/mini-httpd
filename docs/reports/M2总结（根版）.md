## 2. 与 `m1-blocking` 的差异分类（哪些是"必要的状态机改造"，哪些是"epoll 特有"）

### 2.1 必要：从"函数跑到底"到"状态住在对象里"

M1 的 `handle_conn()` 一口气读请求 → 解析 → 写响应，所有中间量都在栈上。
事件循环里一次事件只能做一段 IO，**跨轮次的状态必须住在连接对象里**，这是 M2 真正的改造量：

| M1 的栈上局部量 | M2 的归属 | 为什么 |
|---|---|---|
| 读缓冲（全局 `rbuf`） | `conn.rbuf` + `rlen/roff/rscan` | 每连接一份 |
| 响应头（栈上 `head[1024]` 直接写） | `conn.wbuf` + `wlen/woff` | 没写完的那半截必须活到下一次事件 |
| 文件 fd（`send_file` 里局部打开/关闭） | `conn.file_fd` + `file_off/file_left` | 文件体跨事件发；所有权归连接 |
| `drain` 标志 | `conn.drain_left` + 截止时间 | 收尾从"阻塞等 200ms"改成"事件驱动 + 超时" |
| —— | `conn.phase` / `keep_alive` / `interest` | 状态机位置、连接语义、已注册掩码 |

**这部分与 epoll 无关**：任何"一次事件做一段 IO"的写法（select/poll/io_uring）都得这么改。

### 2.2 epoll 特有：只有在 ET 下才存在的坑

| 事项 | LT（阶段 B 前半） | ET（本版） |
|---|---|---|
| 读/写 | 一次事件一段即可，剩下的内核还会通知 | **必须循环到 `EAGAIN`** —— 否则数据到了没人叫，连接静默挂住 |
| accept | 一次 accept 即可 | **必须 accept 到 `EAGAIN`** —— 否则 `Recv-Q` 一直涨 |
| `EPOLLOUT` | 每个事件重算兴趣即可 | **只在写不动之后挂上**，写完立刻摘掉；常驻 = 空转 |
| `MOD` | 每个事件都发 | 掩码没变就不发 |
| `HUP/ERR` 空转 | 用"整趟有无进展"兜底 | 同左（`moved_total == 0` 才关） |

### 2.3 与 epoll 无关、但顺手补齐的

- `TCP_NODELAY`（**18 倍**，见 ADR-005）：这是"两次写的响应 + Nagle + 延迟 ACK"的经典陷阱，
  换个 I/O 模型照样存在。
- keep-alive：**语义**变化（`CONTRACTS.md` §1b），不是 I/O 变化；`Connection` 的判断进了协议层。
- `_DEFAULT_SOURCE`：`sendfile` 的 feature macro（`_POSIX_C_SOURCE` 不够）。

## 5. 过程中抓到的真问题（都不是"代码写错"，而是"模型想错"）

1. **"改了非阻塞怎么还是阻塞"**（T2.3a → T2.3b 的根因）：非阻塞 + `poll` 只改变"等待时在干什么"，
   改变不了"同时只有一条连接在动"。**谁有数据只有内核知道** —— 不问内核（`epoll_wait`），就只能死等一个人。
   证据：`wchan` 从 `recv` → `poll` → `epoll_wait` 的三步。
2. **ET 下"半路撒手"= 静默挂住**：一次事件读一段就回事件循环，在 LT 下没事，在 ET 下就是丢通知。
3. **`HUP/ERR` 不能当"立刻关"**：`nc -N`（客户端半关闭后还在读响应）也会带这类标志；
   要以 `read`/`write` 的返回值为权威，只在"整趟零进展"时才关（否则 HUP 会反复上报 → 空转）。
4. **`TCP_NODELAY`**：不设就是 44ms 延迟、2233 req/s；设了 2.04ms、48338 req/s。
   "HTTP 服务器为什么都设它"有了第一手答案。
5. **`sendfile` + 分两次写**：头 `send`、体 `sendfile` —— 这是 Nagle 咬人的前提，也是为什么
   `Content-Length` 与"头一次写完"这么重要。
6. **keep-alive 的边界不是"能不能保持"，而是"请求边界清不确定"**：
   声明了 body 却没被消费、解析失败的分支，都必须强制关（否则就是请求走私的入口）。
7. **流水线请求**：上一个 `read` 里可能已经把第二个请求读进来了 → `step_read_req` 必须**先扫缓冲再 read**。
8. **`rscan` 必须跨事件保存**：每个事件从 0 重扫，逐字节到达就是 O(n²)，慢速攻击的 CPU 放大器。
9. **`EMFILE` 不能 sleep 退避**：睡了更没机会回收 fd，等于自锁；ET 下靠下一次边沿自愈。
