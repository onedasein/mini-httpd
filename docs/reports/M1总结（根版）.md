## 三、与 v1 的逐模块对照（T1.7d 的核心）

| 模块 / 决策点 | v1（对照物） | 根版 | 为什么这样更好 / 代价 |
|---|---|---|---|
| 事件等待 | fd 非阻塞 + `poll`（`wait_fd`），"阻塞"只体现在架构上 | **纯阻塞** `read`/`write`，3 个 IO 包装（`conn_read`/`write_all`/`file_read`） | 概念最小；M2 换 epoll 只动这 3 个函数（走查③的答案）。代价：EAGAIN 语义要等 M2 才引入 |
| 读缓冲 | 每条连接 `malloc(72KB)` | `main` 里分配**一份**、串行复用 | 少一条 malloc 失败路径；M2 才需要每连接一份 |
| 请求结构 | 就地改 rbuf（写 `\0`），字段是 NUL 结尾的 `char*` | **只读 rbuf**，字段是「指针 + 长度」借用切片 | 解析器不修改输入、边界显式；代价：必须 `memcmp`/自写十进制解析，`strtoll` 会读越界 |
| 行切分 | `next_line` 就地写 `\0` | 返回切片 + **拒绝裸 CR** | v1 会让 `GET / HTTP/1.1\rX…` 走到 505；根版按 `解析待定项 #10` 直接 400 |
| 方法分流 | 只认 GET/HEAD，其余一律 405 | 40 个**已知方法清单**：已知但不在白名单 → 405；不在清单（`get`/`FOOBAR`/超长）→ **501** | 与 RFC 9110 §15.5.6/§15.6.2 对齐（CONTRACTS §0、ADR-002）；代价：多一张数据表 |
| 版本判定 | `strncmp("HTTP/",5)` → `HTTP/1` 也走 505 | **先看形状**（8 字节 `HTTP/d.d`）再判支持：形状不合 → 400 | 满足决策 #6/#7/#8（`HTTP/1`、尾随空格、空版本都该 400） |
| `path` | `?`/`#` 截断 + `%XX` 解码 + 拒 `%00`/反斜杠 | 同 v1 语义，但**多留 `target` 原始切片** | 日志/排障能看原始请求行；控制字符仍未挡（§3 待定，两版一样） |
| 路径安全 | 逐段拒 `..` + realpath 前缀边界（双保险） | 同左；拼接改为 `memcpy` 且**先检查再拷贝** | v1 用 `snprintf` 天然有界；根版手写拼接，曾有"先拷贝后检查"的 bug（已被 e2e/审查抓住） |
| 目录请求 | 补 `index.html`（没有则 404） | 同左（**一开始漏了**，被 e2e 抓住 11 条断言） | 「不做目录列表」≠「目录一律 404」：`/` 要能取到 `index.html`，`/nolist/` 仍 404 |
| 收尾 | 直接 `close` | **有界 lingering close**（`shutdown(SHUT_WR)` + 200ms/1MB 上限的 drain） | 解决"早退 431 因 RST 被客户端丢掉"。v1 靠"把整个超长 head 读完"绕过同一个问题 |
| 信号 | `signal()`（BSD 语义，**带 SA_RESTART**）+ 阻塞在 poll | `sigaction` **不设 SA_RESTART**，靠 `accept` 的 `EINTR` 退出 | 实测：带 SA_RESTART 时 `kill -TERM` 后进程卡在 accept，exit=124 |
| 测试 | 一套 `tests/run.sh`（55 条，脚本内混着夹具） | 三层：Unity 单测 12 条 + smoke + e2e 61 条；夹具全在 `mktemp -d` | 单测毫秒级可定位到函数；e2e 不往仓库写素材；发布前 ASan/valgrind 三跑 |

## 四、卡住的地方（现象 → 根因 → 出处）

1. **`GET /` 与 `/sub/` 返回 404（e2e 11 条同时红）** → `file.c` 没做「目录请求补 `index.html`」，而 `file.h` 的注释写着"目录 → 404"，与 `CONTRACTS.md` §1 的 200 行打架 → 补上后 11 条同时转绿（`/nolist/` 仍 404）。
2. **`main.c` 编不过**（`parameter 1 has incomplete type`）→ `http.h` 的 `http_err` 改成了匿名 `typedef`，而 `main.c` 仍写 `enum http_err` → 统一为 `typedef enum Tag{…} Name;`（两种写法都能用）。
3. **`make test` 报"全部通过"但一条用例都没跑** → 测试文件是 0 字节/空骨架，Unity 打印 `0 Tests` → Makefile 增加「`0 Tests` 判红」防护；空骨架改名 `.pending`，等规则定稿再落地。
4. **超长请求的 431 客户端收不到** → 服务端 8KB 就早退并 `close`，接收队列还有未读字节 → 内核发 RST，客户端还在写 → 写入失败直接退出，连响应都读不到 → 有界 lingering close（`conn_finish`）。
5. **`SIGTERM` 后进程不退出** → `signal()`/`SA_RESTART` 让 `accept` 被内核自动重启 → 改用 `sigaction` 且不设 `SA_RESTART`（实测 124 → 0）。
6. **小写 `get` 被判成 200**（写实现时差点踩）→ 方法名比较误用 `strncasecmp` → 方法/版本必须**区分大小写**（`memcmp`），只有字段名不区分。`test_request_line` 的 `lowercase get → 501` 是唯一能暴露它的判别用例。
7. **`file.c` 边界检查写在 `memcpy` 之后** → 文档根很长时栈溢出 → 改为先检查再拷贝。
