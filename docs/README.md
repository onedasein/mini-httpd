# docs/ — 文档地图（谁是真源、什么该查哪里）

> 2026-10-13 重组，起因见 `archive/REBUILD-2026-10-13.md`。
> **一条硬规矩：同一件事只能有一个真源。** 真源改了 → 头文件 / 测试 / 实现必须跟着改；
> 参考文档只负责写"从哪儿来"，**不许在那里重新定义**。

## 活文档（在仓库根，路径稳定）

| 文件 | 回答什么问题 | 地位 |
|---|---|---|
| `../README.md` | 这个项目是什么、怎么编怎么跑 | 入口 |
| `../DESIGN.md` | 要写什么 / 架构 / 实现顺序 / 测试策略 | **真源** |
| `../CONTRACTS.md` | 函数契约、状态码表、错误码映射、纪律 | **真源**（先改它，再改代码） |
| `../TASKS.md` | 现在做到哪、下一步打勾 | **真源**（执行视图） |
| `../Makefile` | 构建与测试入口（`debug/release/asan` + `test/e2e/check`） | 机械件，REBUILD 明确保留 |

## docs/ 下（参考资料，非真源）

| 路径 | 内容 | 什么时候看 |
|---|---|---|
| `rfc/RFC与系统调用速查.md` | 报文语法、状态码的 RFC 出处、feature macro / `MSG_NOSIGNAL` / `SO_REUSEADDR` / `nc` 等**实测**结论 | **写解析与拼装函数时手边查** |
| `rfc/解析待定项.md` | 还没拍板的语法歧义（`HTTP/1`、小写 `get`、多空格…） | **写解析器之前先把它清空** |
| `adr/` | 决策记录（背景 / 选项 / 决定 / 后果） | 问"当初为什么这么定"（004=LT 事件循环，005=ET + keep-alive + `TCP_NODELAY`） |
| `method/设计模板.md` | 设计方法论模板（分工、命名规范、测试写法） | 需要方法时 |
| `reports/` | 阶段性报告（`M1总结（根版）.md`、`M2总结（根版）.md`、Rust 对照） | 收口时写、复盘时读 |
| `bench/` | **每次压测的原始数据**（`M2-ET验收.md` = ET 版的 `wrk` + `strace -c`，M4 的起点） | 做优化前先看它，别凭感觉挑优化点 |
| `bench.md` | 压测记录（`tests/bench.sh` 会写它旁边的 `bench/`） | M4 |
| `archive/` | 只读存档：v1 审查报告 / M1 总结、warmup 概念图、本次重构指令 | 当历史读，**别再当规范** |

## 查表手册（写代码时最快的路径）

| 我要… | 去哪 |
|---|---|
| 一个函数的前置 / 失败 / 所有权 | `../CONTRACTS.md` §2 |
| 某个输入该回哪个状态码 | `../CONTRACTS.md` §1（RFC 出处见 `rfc/RFC与系统调用速查.md` §6/§8） |
| 上限是多少（`MAX_*`） | `../src/httpd.h` —— **数字的唯一真源是代码**，`CONTRACTS.md` 只写名字与含义，不抄数字 |
| 这条语法接不接受 | `rfc/解析待定项.md`（**没决策 = 没定**，不许在实现里偷偷定） |
| 以前踩过什么坑 | `rfc/RFC与系统调用速查.md` + `archive/v1-审查报告.md` |
| 为什么这么设计 | `adr/` |

## 三条维护纪律

1. **改语义 → 先改 `CONTRACTS.md` + 写 `adr/` → 再改头文件 → 最后改实现与测试。**
   （顺序反了就会出现 2026-10-13 那次"头文件写 501、契约写 405"的冲突，见 ADR-002。）
2. **存档只读**：`archive/` 里不再新增/更新结论；要更新就写进活文档。
3. **路径稳定优先**：活文档留在仓库根、文件名不改（省得每次都要重新找，对人和对 AI 都一样）。
