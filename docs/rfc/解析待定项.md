# 解析待定项（写解析器之前必须先拍板）

> 用法：每定一条，就在「决定」列写死 + 写出来源（RFC 章节 / 契约 / ADR），把状态改 ✅，
> 并同步 `CONTRACTS.md` §1 的状态码表。**没决策 ≠ 随便定**：不许在实现里偷偷决定。
> 这张表存在的理由：`tests/unit/test_request_line.c` 的每条期望值都必须有唯一出处；
> 一条没定，那条用例的期望值就是猜的。

| # | 语法点 | 候选 | 决定 | 状态 | 依据 / 影响 |
|---|---|---|---|---|---|
| 1 | method 合法但不在白名单（PUT/DELETE/…） | 405（带 `Allow`）／501 | **405 + `Allow: GET, HEAD`** | ✅ | RFC 9110 §15.5.6；ADR-002 |
| 2 | method 是小写 `get` | 400（方法名大小写敏感，`get` ≠ GET）／405（当成"不认识的方法"） | 501(Not Implemented)| ✅ | RFC 9110 §15.6.2 |
| 3 | method 超长（> `MAX_METHOD_LEN`） | 400（语法类）／501（`httpd.h` 注释原话） | 501 | ✅ | 与 #2 一起定，别一个 400 一个 501 |
| 4 | 三段之间多个连续空格（`GET  /  HTTP/1.1`） | 400（严格单 SP）／宽容折叠 | 400 | ✅ | RFC 9112 §3：分隔符只能是单个 SP |
| 5 | 用 `\t` 当分隔符 | 400 | 400 | ✅ | 同上 |
| 6 | `HTTP/1`（缺次版本） | 400 语法不合／505 版本不支持 | 400 | ✅ | RFC 9112 §2.3；影响 `HTTP_ERR_VERSION` 的语义边界 |
| 7 | 版本字段带尾随空格（`HTTP/1.1␠`） | 400 | 400 | ✅ | — |
| 8 | 版本字段为空 | 400 | 400 | ✅ | 与 #4 的"空 target"同类 |
| 9 | target 非 origin-form（`http://host/x`、`*`） | 400（第一版只收以 `/` 开头） | 400 | ✅ | RFC 9112 §3.2 |
| 10 | 行尾只有 `\r` 没有 `\n`（末行被截断） | 400／交给 `http_scan_header_end` 等更多数据 | 400 | ✅ 	 | RFC 9112 禁止裸CR |
| 11 | `Content-Length: 0` 与"没有该 header" | 二者必须可区分（给 `http_request` 加 `has_content_length`） | 正常处理 | ✅ | 影响 M2 keep-alive 的边界计算, RFC 9112 6.3，Content-Length:0 和 没有该header,消息体长度都被定义为0。明确为消息提供了边界 |
| 12 | 重复 `Content-Length` 且值不同 | 400／取第一个 | 400 | ✅ | RFC 9112 §6.3 |

## 定完之后要做的事（顺序别反）

1. 在本表写「决定」+ 状态 ✅；
2. 若是"语义级"决定（比如 #6 改了 `HTTP_ERR_VERSION` 的边界）→ 写一篇 `docs/adr/00X-*.md`；
3. 同步 `CONTRACTS.md` §1 状态码表；
4. 然后再写 `tests/unit/test_request_line.c` 的用例（那时期望值才有唯一出处）；
5. 最后才动 `src/http.c`。
