# ADR-004：事件循环与连接状态机（M2 阶段 B，T2.3b）

- 状态：**已实施**（2026-10-14），待本人复核
- 相关：ADR-001（单线程事件循环）、ADR-003（连接表与 conn 模块）、`TASKS.md` M2 阶段 B、
  `CONTRACTS.md` §2「状态机不变式」

## 背景

阶段 A 之后**服务器仍然是"一次只伺候一条连接"**：fd 虽然非阻塞了，但主循环还是
`accept` 一条 → 在 `handle_conn()` 里把它处理到底（读不到就 `poll` 等），慢客户端照样拖死全服。
实测三路对照（同夹具同手法）：

| 版本 | 慢客户端占住时的第二个客户端 | 服务端 `wchan` |
|---|---|---|
| `m1-blocking`（纯阻塞 `recv`） | `000`（超时） | `wait_woken` |
| 阶段 A（非阻塞 + `poll` 等待） | `000`（超时） | `do_sys_poll` |
| 阶段 B（本 ADR，`epoll` LT） | **`200`** | `do_epoll_wait` |

根因不是"fd 阻塞"，而是"**没人同时看着所有连接**"。非阻塞只改变了"等待时在干什么"，
改变不了"只有一条连接在动"。

## 决定

1. **LT 先行（T2.3b），ET 留到 T2.4**。这一版注册时不带 `EPOLLET`，一次事件只做**一段** IO
   （一次 `recv` / 一次 `send` / 一次 `sendfile` / 一次收尾读），剩下的内核下次还会通知。
   代价：系统调用次数偏多（同一批数据可能要几轮 `epoll_wait`）。收益：把"循环到 `EAGAIN`"
   这件容易写错的事**完整留给 T2.4**，那时只需把 `step_*` 改成循环，其余一行不动。
2. **"下一步 / 该关注什么事件"是推出来的**，不是存出来的：`conn_next_step()` 看字段推出
   `CONN_STEP_*`，`conn_step_events()` 把它翻成 `EPOLLIN`/`EPOLLOUT`。**不额外存 interest**，
   免得"状态"和"注册的事件"两处打架 —— 这类不一致的典型后果是"有数据要写却只关注 `EPOLLIN`"→ 死等。
3. **响应先装进连接的 `wbuf`，再由 `EPOLLOUT` 往外写**（不再在栈上写完直接 `write`）：
   一次事件只做一段 IO，就意味着"没写完的那半截"必须活到下一次事件 —— 它只能住在连接对象里。
4. **文件体走 `sendfile`**，不读进用户态缓冲。理由：把文件读进内存再写，要么每连接常驻一大块
   （4096 连接 × 64KB ≈ 256MB），要么状态机里多一份"半截 body 缓冲"。`sendfile` 用内核
   把文件推进 socket，`file_off` 由内核推进，非阻塞下满了就 `EAGAIN` 等下一次事件。
   HEAD 请求只发头（`file_left = 0`），`Content-Length` 仍是真实大小。
5. **收尾（lingering close）从"阻塞等 200ms"改成"事件驱动的 DRAIN + 截止时间"**：
   进 `DRAIN` 前先 `shutdown(SHUT_WR)`（客户端立刻拿到干净 FIN，能读完刚发的响应），
   然后只读不发，最多 1MB / 200ms，到点由 `sweep_deadlines()` 收掉。
   M1 那版是在 `handle_conn` 里 `poll` 等 —— 那 200ms 是**整台服务器一起等**。
6. **监听 fd 也改非阻塞**，但**不加 `EPOLLET`、也不写 `accept` 循环到 `EAGAIN`**：
   那是 T2.4a 的验收。非阻塞的意义在于"一次假唤醒（`EAGAIN`）不会把整个循环冻在 `accept` 上"。
7. **`EPOLLHUP`/`EPOLLERR` 不当成"立刻关"**：半关闭（对端 `shutdown(SHUT_WR)` 后还在读我们的响应，
   e2e 里的 `printf … | nc -N` 就是）也会带这类标志。做法是照常让当前这一步去试一次，
   **以 `read`/`write` 的返回值为权威**；但如果"硬错误 + 一点进展都没有"，就立刻关
   （否则 `HUP` 会被反复上报 → 空转 100% CPU）。
8. **`g_stop` 与 `epoll_wait` 的竞态用 200ms 超时兜底**，不用 eventfd/self-pipe：
   信号若在"检查 `g_stop`"之后、"进入 `epoll_wait`"之前到达，没有超时就会一直等下去。
   代价是空闲时每 200ms 醒一次（实测 2 秒空闲 0 jiffy CPU）。eventfd/self-pipe 是 M3 的正式解法。
9. **增量扫描游标 `rscan` 存进连接对象**：`http_scan_header_end` 的 `*scan` 一旦每个事件都从 0 重来，
   一个逐字节发满 8KB 头的连接就会把 CPU 放大成 O(n²) —— 慢速攻击的放大器，凭空多出来的那种。

## 代价与已知取舍

- `MAX_EVENTS 64`：一次 `epoll_wait` 最多拿回 64 个就绪事件，其余下一轮（LT 不会丢）。够 M2 验收用。
- 每个事件一次 `epoll_ctl(MOD)`（没做"interest 没变就跳过"的优化）—— 一次系统调用，先求正确。
- `sendfile` 是 Linux/glibc 扩展，需要 `_DEFAULT_SOURCE`（已写进 `src/conn.c` 顶部）；
  这个项目本来就是 Linux-only（`epoll`），不构成新的可移植性负担。
- 仍是一律 `Connection: close`（keep-alive 是 T2.6）。`conn_compact()` 现在**没有活的调用者**
  （处理完就关，残余字节没有下一个请求去读）—— 它仍被单元测试覆盖，T2.6 会重新用上；
  但 keep-alive 开始时必须同时把 `rscan` 归零。
- 退出前手动收干净所有连接（`main` 末尾那个 `conn_next_fd` 循环）：不加也能跑，
  但 valgrind 的「All heap blocks were freed」就不成立了。

## 验收（2026-10-14 实测）

| 项目 | 结果 |
|---|---|
| `make check` | 单测 **19** 条 + e2e **61** 条全绿，零告警 |
| `make e2e-asan` | 61/61 |
| 慢客户端（`nc` 连上不发） | 第二个客户端 **200**，`wchan = do_epoll_wait` |
| 20 条慢 loris 同时挂着 | 正常请求 10/10 成功；收尾后 fd 回落到基线 |
| `strace -c` | 主循环是 `epoll_wait`（614 次 / 80 请求）；**没有 `poll`** |
| 空闲 2 秒 | **0 jiffy** CPU（`EPOLLOUT` 没有常驻 → 不空转） |
| 10MB / 5MB 背压 | 客户端 `SO_RCVBUF=4096` 也能收满（`EPOLLOUT` 路径正确） |
| 并发 200（`xargs -P100 curl`） | 200/200，压测前后 fd 6 → 6 |
| valgrind | `ERROR SUMMARY: 0 errors` + `All heap blocks were freed` |
| `SIGTERM` | exit 0，日志有 `shutdown` |
