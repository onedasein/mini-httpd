# ADR-002 · 方法合法但不在白名单 → 405（不是 501）

- **状态**：已定（本次据此把 `src/http.h` / `src/httpd.h` 的注释从 501 改正为 405）
- **日期**：2026-10-13
- **相关**：`CONTRACTS.md` §1 / §3、`TASKS.md`「M1 验收契约」、`docs/rfc/解析待定项.md` #1

## 背景

2026-10-13 重组前，同一个语义在仓库里有两种写法 ——

| 说 405 的 | 说 501 的 |
|---|---|
| `CONTRACTS.md`/`TASKS.md` 的契约表、`src/main.c` 的映射宏、v1（`http.c`/`main.c`/`http.h`）、你自己的 `docs/rfc/RFC与系统调用速查.md` §6、v1 审查报告 | `src/http.h` 的 `HTTP_ERR_METHOD` 注释、`src/httpd.h` 的 `MAX_METHOD_LEN` 注释 |

这正是 `docs/archive/REBUILD-2026-10-13.md` 抱怨的那类冲突：**"因为没按契约表 → 用例表 → 实现的顺序走，头文件里的错误码定义就飘了"**。

## 依据

- **RFC 9110 §15.5.6**：405 表示"资源不支持该方法"，且**响应必须包含 `Allow`**；501 表示"服务器不认识这个方法"。
- 静态服务器对 PUT/DELETE 回 405 是常规做法（v1 的 55 条 e2e 断言也是 405 + `Allow: GET, HEAD`）。

## 决定

白名单外的方法 → **405 + `Allow: GET, HEAD`**；`HTTP_ERR_METHOD` 的语义**就是**这个。
`src/main.c` 里的 `#define STATUS_METHOD_NOT_ALLOWED 405` 是**唯一的映射点**。

## 后果

- `src/http.h` / `src/httpd.h` 的注释已改为 405（代码行为不变，因为实现还没写）。
- 若将来要改回 501：必须**五处一起动** —— 本 ADR、`CONTRACTS.md` §1、`main.c` 的宏、`TASKS.md` 契约表、e2e 断言。
- 已定：method 的**语法**非法（含非法字符 / 超长）回501
