| # | 现象 | 一开始以为 | 实际原因 | 出处 | 修复 |
|---|---|---|---|---|---|

## 1. 短读：一次 `read` 绝不假定读完

**做法**：`handle_conn` 循环 `conn_read` 往 `rbuf` 里攒，只认「增量找到空行」为边界；
`http_scan_header_end` 保存扫描游标（每次只重扫最后 3 字节，接住被切断的 `\r\n\r\n`）。
`read == 0` 与 `read < 0` 分开处理（前者是 EOF，后者才 `perror` 语义）。

**证据**
- `tests/run.sh` → `逐字节到达也能解析（增量找空行）`：把 31 字节的请求**每字节间隔 20ms** 发出去，仍然 `200 OK`。
- `strace` 抓到的正常路径：`recvfrom(4, "GET / HTTP/1.1\r\nHost: 127.0.0.1:8080\r\n...\r\n\r\n", 73728, 0, ...) = 92`。
- 短读次数统计（echo 那边）与这里同理：读缓冲 73728，超长请求分多次 read。

**已知欠缺**：`rbuf` 是「一个请求一整块」，`hdr_end` 之后的残余字节（pipelining）直接丢弃 ——
v1 每连接只处理一个请求，这是设计选择（T2.6 才做 keep-alive）。

## 2. 短写：所有发送都在循环里，且 `ssize_t` 有符号

**做法**：`write_all()` 循环到写完或出错；`send(..., MSG_NOSIGNAL)`；`EINTR` 重试；
`EAGAIN/EWOULDBLOCK` → `poll(POLLOUT)` 再继续。**没有任何一处把返回值存进 `size_t`。**

**证据**
- `10MB 传输与源文件 cmp 一致`（`cmp -s` 完全一致，10485760 字节）。
- `慢速读 10MB 仍是完整响应体`：把客户端 `SO_RCVBUF` 压到 4096 并每 256KB 停 10ms，制造背压，
  服务端必然经历「发送缓冲区满 → send 返回部分写/EAGAIN → POLLOUT」，仍然 `10485760/10485760` 完整。
- `大文件 Content-Length` = `10485760`，与真实 `stat` 一致（响应边界不靠连接关闭，靠 CL）。

## 3. errno：分类处理，别把「正常现象」当致命错误

| errno | 处理 | 证据 |
|---|---|---|
| `EINTR` | 一律重试（`wait_fd`/`conn_read`/`write_all`/读文件） | 优雅退出测试：SIGTERM 打断 `poll` → 走 `g_stop` 分支收尾，`exit 0` |
| `EAGAIN/EWOULDBLOCK` | 不是错误，`poll` 等就绪后继续 | 见 §2 的慢速读用例 |
| `EPIPE/ECONNRESET/ETIMEDOUT` | 连接级：关这条连接，继续服务 | `传输中途 RST：服务端不许死` → RST 之后 `200` |
| `EMFILE/ENFILE`（accept） | 致命级但不退出：记日志 + 退避 100ms + 继续 | 代码路径 `main.c` accept 分支（需 `ulimit -n` 压测才能真跑到，M3 T3.2 补） |
| `SIGPIPE` | 进程级 `SIG_IGN` **且** 发送用 `MSG_NOSIGNAL`（两道防线） | `strace` 里 `sendto(..., MSG_NOSIGNAL, ...)` |

## 4. 资源：每条早退路径都要还 fd / 还内存

**做法**：`handle_conn` 只有**一个**出口（`goto done`），在那里 `close(sf.fd)`、`http_request_free`、`free(rbuf)`。
`sf.fd` 初值 `-1`，避免「没打开也 close(0)」。主循环里 `close(cfd)` 在 `handle_conn` 之后无条件执行。

**证据**
- `跑完全套后 fd 数量不变（无泄漏）`：套件跑完（含 10MB×2、RST、70KB 攻击）后 `/proc/<pid>/fd` 仍是 **4** 个（= 0,1,2 + 监听 fd）。
- `make asan` + `ASAN_OPTIONS=detect_leaks=1` 跑全套 → 55/55，进程 `exit 0`（LeakSanitizer 有泄漏时会改退出码，所以这条是**真断言**）。
- valgrind 独立复核：`ERROR SUMMARY: 0 errors`、`All heap blocks were freed -- no leaks are possible`。

> 注意一个方法论坑：**若服务端是被 `kill -9` 掉的，LeakSanitizer/valgrind 的退出检查根本不会执行**，
> 「无泄漏」就只是空话。所以 v1 特意做了 SIGTERM/SIGINT 优雅退出（置标志 → 跳出 accept → `return 0`）。

## 5. 并发模型：串行是**故意**的，而且要能被复现

**证据（M2 的对照组，T2.2 直接拿这个跑）**
```
正常请求                      → 200，real 0.007s
慢客户端连上后什么都不发       → /proc/<pid>/wchan = do_sys_poll，State: S (sleeping)
此时第二个客户端 curl -m 3 /   → http_code=000，curl exit=28（超时）
慢客户端一走                  → 立刻 200，time 0.0019s
```
一条空闲连接就能拖死整台服务器；M2 换成 epoll + 非阻塞就是修它。

**为什么 v1 里 fd 已经全是非阻塞**：「阻塞」指的是**架构**（一次一条连接），不是「允许 syscall 挂住进程」。
从第一天就用 `O_NONBLOCK` + `poll`，M2 只需把「等就绪」那一行从 `poll` 换成 `epoll_wait`，IO 包装层不用重写。

## 6. 安全

| 项 | 做法 | 证据 |
|---|---|---|
| 路径穿越 `..` | 逐段判断（不用 `strstr(path,"..")`，否则误杀 `a..b`） | `--path-as-is /../Makefile` → **400**，且响应体里**没有** Makefile 内容 |
| 编码绕过 | `%XX` 只解一次；解码出 `%00`、`\` 一律 400 | `/%2e%2e%2fMakefile` → 400；`/..%2fMakefile` → 400；`/%00` → 400 |
| 符号链接逃逸 | **双保险**：先拒 `..` 段，再 `realpath()` 后前缀比对仍在 www 根之下 | `ln -s /etc/passwd` → **403**；`ln -s ../Makefile` → **403**；www 内正常软链 → 200 |
| 目录列举 | 目录补 `index.html`，仍不是普通文件就 404 | 无 index 的目录 `/nolist/` → 404 |
| 缓冲区 | 所有拼接只用 `snprintf` + 长度检查；无 `strcpy/strcat/sprintf/gets` | `grep -nE '\b(strcpy\|strcat\|sprintf\|gets\|alloca)\s*\(' *.c` → **无输出** |
| 上限防护 | 单行 8KB / 总量 64KB / URI 2KB / header 64 个 / body 1MB | 单行 20000B → 431；总量 70KB → 431；URI 2500B → 414；`Content-Length: 9999999` → 413 |
| `SIGPIPE` | `SIG_IGN` + `MSG_NOSIGNAL` | 见 §3 |
| 信息泄漏 | 错误页只有状态码 + 固定文案，**不回显请求路径、不含绝对路径**；日志里的 method/target 经 `sanitize()` 把控制字符打成 `?`（防日志伪造） | `send_error()` 的 body 与 `sanitize()` |

**已知欠缺（明确留给后面）**：空闲超时（T3.1，所以 slow loris 目前能挂住）；连接数上限（只有 EMFILE 兜底，没有预防）；
没有 `Host` 白名单/虚拟主机；不做 TLS。

## 7. 协议

| 项 | 结果 | 证据 |
|---|---|---|
| `Content-Length` 与 body 一致 | 一致（408 / 10485760 / 0） | 三条 `chk` + 大文件 `cmp` |
| `HEAD` 不发 body | 发了 137 字节 = 只有头 | `HEAD 不发 body`，且 Content-Length 仍是 408 |
| 方法白名单 | 405 + `Allow: GET, HEAD` | `PUT`/`DELETE` → 405，`Allow` 头存在 |
| HTTP/1.0 / `Connection` | 一律 `Connection: close`（短连接） | 响应头恒有 `Connection: close` |
| header 名大小写不敏感 | `hOsT`、`cOnNeCtIoN: CLOSE` 均 200 | 两条 raw 用例 |
| 多个同名 header | 允许（不合并、不报错） | `X-Dup: 1` + `X-Dup: 2` → 200 |
| 行尾 | 标准 CRLF；宽容接受裸 LF | `裸 LF 行尾也被宽容接受` |
| HTTP/1.1 缺 Host | 400（RFC 9112 要求） | `缺 Host 的 HTTP/1.1 → 400` |
| 未知版本 | 505 | `HTTP/2.0 → 505` |
| 版本历史 | 只支持 1.0/1.1，`HTTP/` 开头但不认识 → 505，其他 → 400 | 代码 + 用例 |

**已知欠缺**：keep-alive 未实现（T2.6）；不支持 chunked、Range、absolute-form 请求目标（`GET http://host/p` → 400）；
请求体不消费（只支持 GET/HEAD）。

## 8. 可观测性

- 每条请求一行日志：**peer 地址 + 方法 + target + 状态码 + 字节数**，例如
  `127.0.0.1:47083       GET  /                                        -> 200  408B`
- 启动时打印监听地址与 **www 根的 realpath**（排查「404 到底在找哪个目录」最有用的一行）。
- 错误走 `stderr` 并带 `strerror(errno)`；`accept` 的致命错误（EMFILE）也有明确日志。
- 原始字节：v1 运行时不打 hex dump（echo 热身里的 `dump_bytes` 是那个阶段的工具）；
  看线上真实字节用 §9 的办法。

**已知欠缺**：没有请求耗时、没有慢请求告警、没有日志级别开关 —— M3/M4 再谈。

## 9. 想复现这套结论，照抄这几条

```bash
cd warmups/httpd/v1 && make debug && bash tests/run.sh          # 55 条
make asan && ASAN_OPTIONS=detect_leaks=1 bash tests/run.sh ./build/asan/httpd_v1
# 看内核侧真实报文（T1.1）
strace -f -e trace=recvfrom,sendto -s 300 -o /tmp/tr.txt ./build/debug/httpd_v1 127.0.0.1 8080 www &
curl -s -o /dev/null -H 'X-Test: hello' http://127.0.0.1:8080/ ; grep -E 'recvfrom|sendto' /tmp/tr.txt
# 复现「慢客户端拖死全服」（M2 的靶子）
./build/debug/httpd_v1 127.0.0.1 8080 www & nc 127.0.0.1 8080 &   # 慢客户端占住唯一连接
curl -s -m 3 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/   # → 000，exit 28
```
